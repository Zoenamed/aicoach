# 维度分离路由规则

> 根据用户提问的话题，路由到对应评估维度，用该维度的水平决定回答策略。

## 话题→评估维度映射

| 话题关键词 | 评估维度 | 说明 |
|-----------|---------|------|
| Python、数据结构、算法、编程 | `programming` | 编程基础能力 |
| Transformer、Attention、Embedding、LLM原理 | `ml_fundamentals` | AI/ML 理论基础 |
| Prompt、API调用、ChatGPT、Claude | `llm_practice` | LLM 使用经验 |
| RAG、检索、分块、向量数据库、Embedding检索 | `rag` | RAG 系统相关 |
| Agent、工具调用、多智能体、工作流 | `agent` | Agent 开发经验 |
| 部署、监控、CI/CD、性能优化、线上 | `production` | 生产环境经验 |
| 微调、SFT、RLHF、DPO、训练 | `model_training` | 模型训练相关 |

## 路由逻辑

```
1. 识别用户提问涉及的维度
2. 查找该维度的当前评估水平（entry/intermediate/advanced）
3. 加载对应的教学策略模板（level-entry/intermediate/advanced.md）
4. 用该策略生成回答
```

单条消息可能跨多个维度——取涉及维度中的**最低水平**作为主回答策略，
对高水平维度的部分适当提升深度。

## 不均匀水平处理策略

用户各维度水平可能差异很大。处理原则：

1. **独立追踪**：每个维度单独记录水平，不做平均
2. **就低不就高**：不确定时按较低水平回答（容错优先）
3. **多层次回答**：核心内容用较低水平讲，末尾补充一段较高水平的延伸
   - 格式：「如果你想深入了解：[高水平补充内容]」
4. **主动确认**：发现维度差异大时，向用户确认
   - 例：「你编程很熟，但 Agent 这块似乎刚接触？我调整下讲解方式」

## 动态调整规则

用户反馈触发水平调整：

| 用户反馈 | 调整动作 |
|----------|----------|
| "太简单了" / "我知道这个" | 该维度水平 +1（entry→intermediate 或 intermediate→advanced） |
| "太难了" / "没听懂" | 该维度水平 -1（advanced→intermediate 或 intermediate→entry） |
| "这部分我熟，其他的不太懂" | 精确调整对应维度 |

调整后立即生效，后续回答使用新水平。

## 记忆新鲜度

- 如果某维度的评估是 >7 天前做的，下次涉及该维度时插入一个轻量验证问题
- 格式：自然融入对话，不要显得像测试
- 例：「对了，你之前说在学 RAG，最近有新进展吗？」
